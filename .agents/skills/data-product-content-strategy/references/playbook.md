# Content strategy playbook

## Fictional product context

FlowLake is a fictional incremental ingestion product. A synthetic source-to-warehouse sample works, but real data needs approved credentials and reconciliation. Sample completion is not production approval. Update, delete, late-arrival, freshness, and recovery behavior must be verified rather than assumed.

## Decision to resolve

Build around source/destination behavior, schema changes, late arrivals, reconciliation, freshness, governance, and workload cost. Require a verified example or defensible evidence for each proposed connector or performance topic.

## Task-specific method

Cover source and schema behavior, representative datasets, reconciliation, freshness, governance, deployment, and cost. A polished sample dashboard alone is weak evaluation proof.

## Application brief

Deliver: A prioritized portfolio, cluster map, production briefs, distribution plan, and maintenance responsibilities. Explain why the first items deserve the available effort.

Do not assume missing capabilities or report proposed tests as completed. A useful answer identifies what is known, finishes the requested artifact within that scope, and names the next bounded verification when needed.

## Review criteria

Do not create programmatic pages unless each has distinct user value and reliable source data. Do not promise rankings or replace a requested new-content plan with an unsolicited refresh project.

The [shared method examples](shared-methods.md) provide additional templates and cross-product examples; apply only those that fit the product scope.
